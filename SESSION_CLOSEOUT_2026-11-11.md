## Синхронизация и публикация
1. Обычный путь доставки — `GitHub main → «Обновить Phantom» на Windows → локальный проект → тестовый AEZA`. Использовать повторно используемый `tools/phantom_sync.py`, а не старые одноразовые `PublishHeader/PublishSite`-сценарии.
2. Синхронизатор работает по pinned commit SHA, проверяет Git blob SHA/локальные конфликты, делает резервные копии, сравнивает SHA-256 на AEZA, загружает только изменившиеся ресурсы и выполняет HTTP-проверку. Подробности — `docs/PHANTOM_SYNC_WORKFLOW.md`.
3. **Не публиковать на `mdis.ru`.** Снять `noindex` допустимо только на этапе переноса в production по отдельному регламенту.
4. Исторические локальные `STATUS.md`, `HANDOFF.md`, `README_проекта.md` не заменять снимками из GitHub. Дополнять их локально с сохранением истории; текущие GitHub-правила находятся в `AGENTS.md`, `prompts/README.md` и этом closeout.
5. После публикации проверять: светлая/тёмная тема; 375/768/1024/1440 px; единое меню и мобильная версия; логотип Phantom; навигационные полосы; межстраничные переходы; `noindex`; формы; SHA-256 и HTTP.

### Параллельная разработка страниц

- В `prompts/` подготовлены и нормализованы промпты `01`–`24`.
- Каждый промпт выполняется отдельным page-agent в своей branch/worktree от актуального `main`.
- Page-agent не меняет shared-файлы, страницы других задач, `AGENTS.md`, `phantom-home.html`, общие CSS/JS, header/footer. Нужные общие изменения перечисляются в `Integration manifest`.
- Page-agent не публикует на AEZA и не сливает ветку в `main`.
- После каждой волны один Integrator принимает ветки, выполняет shared-изменения, cache-bust и единый QA.
- Точный порядок волн и зависимости поддерживаются в `prompts/README.md`.

### Стартовая волна

Промпты `01`–`06` можно запускать одновременно в шести отдельных чатах. Перед запуском каждый новый чат должен:
1. взять актуальный `main`;
2. прочитать `AGENTS.md`;
3. прочитать `prompts/README.md`;
4. выполнить только свой конкретный промпт;
5. в финале вернуть branch, base SHA, commit SHA, изменённые файлы, проверки и `Integration manifest`.
