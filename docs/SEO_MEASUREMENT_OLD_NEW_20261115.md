# МДИС / Phantom — измерение SEO и B2B-заявок до и после миграции

**Дата:** 15 ноября 2026 года  
**Объекты:** действующий сайт `https://mdis.ru/` (production / старый сайт) и новый сайт Phantom (пока тестовый `/mdis-preview/` на AEZA).  
**Принцип:** *не начинать новую переделку дизайна*. Сначала устранить индексационные и технические барьеры, установить исходные показатели, выбрать поисковые кластеры, улучшить 5–10 коммерческих страниц и измерить качество заявок.

## 0. Ключевое различие двух контуров

| Контур | Состояние | Разрешённые действия |
|---|---|---|
| Старый `mdis.ru` | Действующий публичный сайт | Снимать baseline SEO/аналитики с имеющихся аккаунтов, краулить, изучать исторические 3–6 месяцев. **Не менять код, DNS, настройки, счётчики без отдельного разрешения владельца production** |
| Новый Phantom на AEZA | Preview, **55 HTML с `noindex, nofollow`** в GitHub | Статический/браузерный/лабораторный краулинг, тест маршрутов, метаданных и скорости. **Не открывать preview для поисковой индексации**, не засорять production-аналитику тестовыми визитами |
| Новый Phantom на `mdis.ru` после отдельного запуска | Планируемый сайт-замена | По утверждённой карте URL и даты релиза снять запрет на индексацию, проверить `robots.txt`/`sitemap.xml`, 301, каноникалы, включить согласованную аналитику и отслеживать динамику |

Если старый и новый сайты публикуются последовательно на **том же домене `mdis.ru`**, свойства домена в Яндекс Вебмастере и Google Search Console обычно сохраняются; не требуется выдавать новую миграцию за новый независимый домен. Уникальный счётчик Метрики для preview не нужен. Исторические данные счётчика и CRM следует сохранить для сравнения, не начинать измерения с нуля без причины.

## 1. Шесть потоков данных — одинаковый срез «до → после»

| Инструмент | Что собрать со старого сайта | Что проверить на новом | Где требуется доступ |
|---|---|---|---|
| **Яндекс Вебмастер** | Объём индексируемых/исключённых URL; причины исключения; поисковые запросы, клики, показы, CTR, позиции; ошибки обхода, региональность | URL после редиректов, исключения `noindex`/дубли/404, страницы в поиске, обход, стабильность региональности и позиции | Владелец делегирует read-only/частичные права к `mdis.ru` |
| **Google Search Console** | Performance (Search: клики, показы, CTR, средняя позиция); Coverage/Pages; выбранные Google canonical; Core Web Vitals | Каноникализация и индексация новых URL после релиза, пересчёт кликов/показов, статусы sitemap | Доступ к свойству `mdis.ru` или делегирование в GSC; Domain property — через DNS при первичном создании |
| **Яндекс Метрика + CRM** | Существующий ID счётчика, цели и история заявок; сегменты `organic / direct / referral / ads`; источники, landing pages, реальные CRM-статусы | Корректность сбора только на production, события `mailto` и формы, валидация offline lead-событий и сохранение источника | Администратор Метрики и ответственный за CRM; без доступа нельзя подтверждать цели и качество |
| **Screaming Frog / аналог** | Полный crawl URL/код ответа/метаданные/hreflang/canonical/редиректы/битые ссылки/дубли; экспорт CSV | Локальный crawl 55 страниц, полный обход на тестовом AEZA, затем production-краулинг; сравнение изменений | Для публичного обхода чаще не нужна авторизация; может потребоваться доступ через relay |
| **PageSpeed Insights / CrUX** | Mobile/Desktop лабораторные PSI и полевые LCP/INP/CLS в точках с достаточной выборкой | Mobile/Desktop Lighthouse до релиза; после релиза 28-дневные полевые CrUX по URL или origin, если данные появятся | Публичный URL; CrUX может не содержать статистику для низкотрафиковых B2B-страниц |
| **Wordstat + SERP** | Частотность кластеров, регионы, коммерческий интент, сайты-конкуренты, пересечение запросов с посадочными | Карта запросов по 5–10 страницам, исключение каннибализации и мета-дублирования | Яндекс ID для Wordstat; выбор целевых регионов подтвердить с продажами |

**Периоды:** baseline **90 дней** до согласованной даты миграции, дополнительно тренд **180 дней** для сезонности; после — недельные срезы 1/2/4/8/12 недель. Не сравнивать неполную неделю с полной и не приписывать сезонные отклонения только редизайну.

## 2. SEO: сначала обязательные технические барьеры

1. **Снять baseline старого сайта** до любого переключения. Экспортировать списки старых URL из Яндекс Вебмастера/GSC, sitemap, Screaming Frog, а также топ страниц и запросов. Создать таблицу `старый URL → новый URL → 200/301 → canonical → владелец`.
2. **Новый сайт НЕ готов к production-индексации автоматически**: в `main` все 55 канонических HTML имеют `noindex, nofollow` намеренно для тестового preview. Нельзя просто выложить этот HTML в production и ожидать поискового трафика. При релизе — отдельная операция по строго утверждённым файлам, настройке `robots.txt`, `sitemap.xml` и X-Robots-Tag.
3. **Корень и URL-архитектура:** сейчас `phantom-home.html` — главная preview, а `index.html` — **интеграция Phantom и CRM**. Для production определить правильный маршрут главной `/`, реальный slug страницы CRM и 301 с прежних URL. Нельзя механически привязать текущий `index.html` к корню без маршрутизации.
4. **Редиректы:** ранее существовавшие значимые пути `/catalog/…`, `/solutions/…`, `/services/…` и старые ссылки на документы сверять по фактическому crawl. 301 должны вести на соответствующую новую страницу/раздел, а не массово на главную. Не удалять документы без необходимого переноса.
5. **Дубли/каноникалы:** у каждой индексируемой новой страницы задать само-каноникал конечного production URL; проверить meta title/description, один H1, текстовые ссылки, robots, sitemap. Preview canonical не должен указывать на relay. Одинаковые URL с разными параметрами нормализовать.
6. **Скорость:** измерить основные шаблоны mobile/desktop и устранить проблемы LCP/INP/CLS только на приоритетных страницах. По возможности избежать загрузки тяжёлых исходных PDF/схем при открытии HTML.
7. **Разметка/безопасность:** проверить редиректы HTTP→HTTPS, 4xx/5xx, размеры ответов, `mailto`/`tel`, картинки/alt, и отсутствие внешнего hotlink-контента. Продуктовые утверждения брать только из подтверждённой документации.
8. **Сохранность SEO-данных:** выгрузить предыдущие отчёты и сохранить прежнюю историю Метрики и CRM. При изменении структуры URL отдельно проверить поисковые сниппеты и данные индексации после релиза.

## 3. Яндекс Метрика: события и качество B2B-лидов

**Известный факт о новом сайте:** формы в `phantom-home.html`, `phantom-active.html`, `phantom-boards.html`, `attestation-fsk-ees.html` создают черновик **`mailto:`**. Это НЕ подтверждение отправленного письма и НЕ CRM-лид.

Согласовать с отделом продаж и завести **разные уровни событий**:

| Уровень | Событие / поле | Что это означает |
|---|---|---|
| Микро | `open_product`, `view_document`, `click_phone`, `click_email`, `mail_draft_open` | Интерес, нажатие, подготовка черновика. **Не считать заявкой или выручкой** |
| Входящий лид | `received_inquiry` (CRM/offline) | Письмо фактически получено, обращение зарегистрировано |
| Квалифицированный B2B | `qualified_b2b` (CRM/offline) | Компания/проект/тип задачи подтверждены менеджером |
| Продвижение сделки | `tech_consultation`, `proposal_sent`, `opportunity_won` | Качественные следующие шаги — данные CRM, не автоматически созданные при просмотре HTML |

**Критически важно:** не отправлять в Метрику email, ФИО, телефоны, свободный текст форм или исходные тела `mailto`. Если источник для запроса не удаётся технически связать с CRM без персональных данных, фиксировать долю атрибутированных лидов отдельно и **не придумывать** attribution. События счётчика Метрики требуют фактического ID и конфигурации цели `reachGoal` на нужном сайте.

**Политика/согласие:** официальные документы `privacy-policy.html` и `cookie-policy.html` переносим без редактирования содержания. Они описывают Яндекс.Метрику и запрос согласия при первом посещении; прежде чем подключить аналитические cookies на новом production, нужно реализовать соответствующее техническое поведение (до согласия не загружать аналитический счётчик, дать выбор и возможность изменить его) с утверждением владельцем сайта. **Не публиковать фиктивный баннер и не подключать аналитику на preview по умолчанию.** Действующий `mdis.ru` и его счётчик не менять в рамках GitHub-задачи.

## 4. Приоритетные коммерческие страницы нового сайта (первая волна, кандидаты)

Это **не рейтинг по трафику** — ранжирование возможно только после экспорта Вебмастера/GSC/Wordstat/CRM.

1. `telephone-recording.html` — запись телефонных переговоров
2. `dispatcher-recording.html` — запись диспетчерских переговоров
3. `ip-telephony.html` — запись SIP/IP-телефонии
4. `selective-recording.html` — селективная запись
5. `phantom-catalog.html` — каталог аппаратных/программных конфигураций
6. `phantom-active.html` — продукт Phantom Active
7. `electroenergetika.html` — отраслевой спрос в электроэнергетике
8. `aviation-transport.html` — решения для авиации и транспорта
9. `index.html` — интеграция Phantom и CRM (**в production нужен отдельный канонический URL, не `/`**)
10. `phantom-home.html` — входная/общая конверсионная страница (**в production должна соответствовать утверждённой главной**)

Для каждой: кластер коммерческих запросов → целевой интент → сравнение ТОП-10 → подтверждённое предложение/фактология → title/H1/description → внутренние ссылки → CTA → мобильное качество → целевое событие → качество запроса в CRM. Не «докручивать» все 55 страниц равномерно.

## 5. Управленческая панель

Один регулярный срез, раздельно `old_before` и `new_after`, с полями:

`period_start,period_end,site_phase,search_engine,landing_url,device,region,query_cluster,impressions,clicks,ctr,avg_position,indexed,excluded_reason,organic_sessions,contact_clicks,mail_drafts,crm_inquiries,qualified_leads,proposals,won_opportunities,attributed_share,lcp,inp,cls,source_notes`.

Не складывать показатели Метрики и GSC как идентичные и не смешивать трафик/конверсию одного домена за одинаковый период при переключении версии сайта.

**Ключевые KPI:** число квалифицированных B2B-лидов по органическому источнику, доля квалифицированных среди полученных обращений, число предложений/договоров, доля лидов с известным источником, число приоритетных целевых страниц в индексе. Клики, видимость и Core Web Vitals — диагностические KPI.

## 6. Что нужно от владельцев систем

- **Яндекс Вебмастер:** делегировать доступ к `mdis.ru` для чтения/аудита индексации, обхода, запросов (без изменения index/robot на текущем сайте).
- **Google Search Console:** доступ к существующему свойству `mdis.ru`; если свойства нет — добавить Domain property с DNS-подтверждением у администратора домена. Не передавать пароли или DNS-ключи в переписке.
- **Яндекс Метрика:** выдать доступ к существующему счётчику, сообщить его **ID** и существующие цели; проверить старый production отдельно. Новый сайт после релиза использовать с контролем домена, согласованной политикой и технической системой согласия.
- **CRM/отдел продаж:** согласовать статусы `получено → квалифицировано → КП → сделка`, правила качества B2B-лидов, ответственного за еженедельный экспорт обезличенных итогов.
- **Screaming Frog:** выгрузить crawl старого `mdis.ru` и crawl нового preview (в рамках доступа к relay), экспорт CSV. Free-версия может ограничивать объём URL; определить объём до выбора лицензии.
- **PageSpeed Insights / CrUX:** проверить эти же 5–10 посадочных страниц; учитывать, что field data не появится, если нет достаточной выборки.
- **Wordstat:** подтвердить целевые регионы продаж, провести сбор частотности по 5–10 кластерам, исключить информационные запросы без коммерческого интента.

## 7. Приёмка и ограничения

**Сейчас:** можно выполнить статический и браузерный QA нового сайта и публичные диагностические проверки старого. **Нельзя** извлечь приватные данные индексации/заявок без аккаунтов, заявить реальные значения кликов/лидов без экспорта, активировать production-счётчик/robots или менять старый Bitrix без разрешения.

**Отдельное go-live решение:** провести URL mapping+301, отменить preview-only `noindex` **только при выпуске production**, убедиться в точных конечных адресах canonical/sitemap и подключить утверждённую аналитику с корректным consent. Запись результатов в проект не является опубликованным релизом.

Источники и справки: [Яндекс Вебмастер — права](https://yandex.ru/support/webmaster/ru/service/rights-management), [Google Search Console — типы свойств](https://support.google.com/webmasters/answer/34592), [Яндекс Метрика — цель reachGoal](https://yandex.ru/support/metrica/ru/objects/reachgoal.html), [CrUX и PSI](https://developer.chrome.com/docs/crux/methodology/tools), [Wordstat — регионы](https://yandex.ru/support2/wordstat/ru/interface/new).
