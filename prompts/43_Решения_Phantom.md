# Промпт для Codex: создать локальную страницу «Решения» для нового сайта Phantom / МДИС

Ты работаешь в репозитории:

`Mixerland1/phantom-product-audit`

Базовая ветка: `main` (работа — в отдельной page-ветке).
Нужно **сразу создать и встроить в новый сайт локальную верхнеуровневую страницу «Решения»** как перенос реального раздела старого сайта:

https://mdis.ru/solution/

# 4. Главная задача страницы

Пользователь должен за один экран понять:

```text
В какой отрасли работает организация?
→ открыть соответствующую страницу решения
```

`solutions.html` не должна повторять детальные тексты восьми отраслевых страниц.

Для каждой отрасли:

- 1 короткое описание задачи;
- 1–2 подтверждённых характерных сценария;
- локальная ссылка;
- при необходимости — короткий factual marker.

# 20. Не определять конфигурацию только по отрасли

Это обязательный note.

Например:

две энергетические компании могут использовать:

- разные АТС;
- разные количества каналов;
- разные поколения Phantom;
- разные серверы;
- разные требования к резервированию.

Следовательно, карточка отрасли — это вход в сценарий, а не готовая спецификация.

# 33. Визуальное оформление

Страница должна выглядеть как **industry solutions hub**.

Использовать:

- общий header;
- общий footer;
- hero rhythm;
- 8 отраслевых карточек;
- краткие descriptions;
- аккуратные industry visual cues;
- decision flow;
- related product/scenario links;
- light/dark.

Не использовать:

- восемь разных stock photos;
- cliché icons как единственное содержание;
- логотипы клиентов вместо отраслей;
- большие числовые KPI без актуального источника.

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
- Не менять production `mdis.ru`.

### Финальный отчёт

Помимо обычного отчёта промпта обязательно добавить `Integration manifest`: созданные page-owned файлы, необходимые изменения общих файлов, зависимости, выполненные и невыполненные проверки.
