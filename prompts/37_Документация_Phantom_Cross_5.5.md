# 10. Не копировать PDF в HTML

Новая support-page не должна воспроизводить:

- оглавление каждого PDF;
- длинные инструкции;
- скриншоты всех интерфейсов;
- команды установки;
- конфигурационные файлы.

Страница — это **точка входа в документацию**.

Подробности остаются в официальных руководствах.

---

# 11. Не обязательно копировать сами PDF в репозиторий

Предпочтительный вариант:

```text
локальная HTML-page
→ официальный PDF на mdis.ru
```

Причины:

- документация может обновляться;
- официальный файл остаётся источником истины;
- нет риска держать в GitHub устаревшую копию.

Если проект уже принял решение хранить docs локально — следовать существующей архитектуре.

Не создавать вторую систему хранения без необходимости.

---

# 12. Если PDF сохраняются локально

Только если это соответствует существующему проектному workflow:

- использовать точные актуальные файлы;
- не менять имена внутри документа;
- сохранить исходный PDF без преобразования;
- указать source URL;
- проверить hash/размер;
- не редактировать PDF в рамках этой задачи.

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
