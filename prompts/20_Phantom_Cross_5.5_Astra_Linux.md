- `AGENTS.md`;

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

# 1. Главный редакторский принцип

`Phantom Cross` — это **программная платформа / программный комплекс МЦКРС «Фантом»**, а не отдельный аппаратный сервер.

Не создавать впечатление, что:

- Phantom Cross — отдельная модель регистратора наряду с Phantom Pro / PC / MICRO / Ultra;
- Phantom Cross 5.5.2 — это отдельное устройство;
- любая аппаратная модель автоматически поддерживает Cross 5.5.2 без проверки;
- все функции Cross 5.5.2 есть во всех исторических версиях Phantom.

Правильная логика:

> Phantom Cross 5.5.x — современная программная платформа МЦКРС «Фантом» для Astra Linux. Она разделяет функции записи, хранения, Web-доступа, мониторинга и администрирования на отдельные программные компоненты и может работать как на одном сервере, так и в распределённой архитектуре.

# 7. Архитектура Phantom Cross

Официальная инструкция 5.5.2 разделяет систему на основные и дополнительные компоненты.

## Основные компоненты

### Phantom Server

Назначение:

- хранение метаданных в PostgreSQL;
- хранение и обслуживание записей;
- управление пользователями и доступом;
- контроль лицензирования.

### Phantom Logger

Назначение:

- запись аудиоданных;
- работа с аппаратными платами и/или VoIP-трафиком;
- передача данных на сервер.

### Phantom Web App

Назначение:

- Web-интерфейс Phantom Cross;
- работа с записями;
- администрирование системы.

### Phantom Active Channel

Назначение:

- онлайн-прослушивание каналов.

### Phantom Smart Player

Назначение:

- воспроизведение записей.

Эти пять компонентов можно использовать как центральный архитектурный блок страницы.

Не переименовывать компоненты по собственному усмотрению.

# 10. Базовый сценарий «3-в-1»

Документация 5.5.2 описывает базовый сценарий:

```text
Сервер + Логгер + Web-интерфейс на одном сервере
```

Он называется:

```text
сценарий установки «3-в-1»
```

Документ указывает, что он:

- является базовым и распространённым;
- подходит для первичной установки;
- подходит для тестовых систем и систем средней нагрузки;
- не ограничивает последующее масштабирование;
- компоненты при необходимости могут быть вынесены на отдельные серверы.

Это важный центральный блок.

H2:

```text
От «3-в-1» до распределённой архитектуры
```

Не писать:

```text
3-в-1 подходит для любой нагрузки
```

или:

```text
масштабирование не имеет ограничений
```

# 14. Дублирующий сервер

Руководство администратора 5.5.2 подтверждает:

- возможность указать дублирующий сервер;
- использование отдельной машины для резервной копии записей;
- передача записей:
  - практически сразу, с задержкой около одной минуты;
  - либо по расписанию.

Использовать H2:

```text
Копия записей на отдельном сервере
```

Текст:

```text
Если требования эксплуатации предусматривают отдельную резервную копию, Phantom Cross 5.5.2 позволяет передавать записи на дублирующий сервер. Передача может выполняться в обычном режиме или по расписанию.
```

Обязательно:

```text
Дублирующий сервер — это механизм передачи копий записей, а не автоматически полноценный отказоустойчивый кластер.
```

Не писать:

- active-active;
- seamless failover;
- zero data loss;
- HA-cluster,

если отдельная документация этого не подтверждает.

# 55. Критерий готовности

Работа считается выполненной, если:

- создан `phantom-cross.html`;
- Cross представлен как ПО, а не отдельный сервер;
- показана актуальная документация 5.5.2;
- корректно разведены версии 5.5.0 и 5.5.2;
- указаны подтверждённые Astra Linux 1.7.8 и 1.8.3;
- описаны основные компоненты;
- описан сценарий 3-в-1 и распределение компонентов;
- показаны минимальные требования;
- раскрыты роли и фильтры;
- корректно описан дублирующий сервер;
- monitoring показан как отдельный эксплуатационный инструмент;
- VoIP и аппаратные платы показаны как разные источники записи;
- ПО №3128 отделено от промышленного реестра комплекса;
- использован реальный кейс 64 комплектов на Astra Linux;
- Cross связан с главной и каталогом;
- production `mdis.ru` не затронут.

# 56. Формат отчёта после выполнения

После непосредственного внесения изменений коротко сообщи:

1. какие файлы созданы;
2. какие файлы изменены;
3. как разведены Cross 5.5.0 и 5.5.2;
4. какие компоненты архитектуры показаны;
5. как реализован блок 3-в-1 / distributed;
6. какие требования Astra Linux использованы;
7. как описаны роли и дублирование;
8. как показан мониторинг;
9. какие реестровые факты добавлены;
10. какие ссылки стали локальными;
11. какие проверки выполнены;
12. какие проверки невозможно было выполнить без браузера или тестового стенда.

Не составляй новый план. Сразу реализуй страницу и необходимые точечные связи.
