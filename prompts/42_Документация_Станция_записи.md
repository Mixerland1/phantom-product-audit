# 10. Что извлечь из ТУ для карточки

Перед публикацией открыть документ и проверить:

- точное наименование изделия;
- обозначение ТУ;
- редакцию;
- дату;
- разработчика/изготовителя;
- область применения;
- относится ли документ ко всей станции или конкретному исполнению.

В карточке показывать максимум:

```text
Обозначение
Редакция / дата
Тип документа
```

Не переносить весь состав требований в HTML.

---

# 11. ТУ ≠ сертификат

Не помещать Technical Conditions в группу:

```text
Сертификаты
```

или:

```text
Разрешительные документы
```

ТУ — самостоятельный технический нормативный документ изготовителя.

Если `certificates.html` существует:

не дублировать ТУ туда, если архитектура страницы сертификатов предназначена именно для:

- сертификатов;
- деклараций;
- лицензий;
- аттестаций;
- государственных реестров.

---

# 12. ТУ ≠ доказательство текущей сертификации

Наличие ТУ не означает автоматически:

- сертификацию ФСТЭК;
- аттестацию Россетей;
- соответствие всем отраслевым нормам;
- действующую декларацию;
- включение в реестр.

Не делать таких выводов.

# 43. Критерий готовности

Работа считается выполненной, если:

- создан `support-stantsiya-zapisi.html`;
- страница доступна из `support.html`;
- product-page связан с документацией;
- опубликованы ровно актуальные документы;
- ТУ и руководство чётко разведены;
- обозначение ТУ проверено;
- редакции/версии не придуманы;
- ТУ не выданы за сертификат;
- версия ПО станции не придумана;
- для другой редакции есть путь в поддержку;
- production `mdis.ru` не затронут.

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.
