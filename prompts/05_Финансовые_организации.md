# Промпт для Codex: создать страницу «Финансовые организации»

Репозиторий: `Mixerland1/phantom-product-audit`  
Базовая ветка проекта: `main`.

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
- Не менять production `mdis.ru`.

### Финальный отчёт

Помимо обычного отчёта промпта обязательно добавить `Integration manifest`: созданные page-owned файлы, необходимые изменения общих файлов, зависимости, выполненные и невыполненные проверки.

## 3. Что нельзя приписывать Phantom

Старая страница слишком широко связывает запись переговоров с «банковской безопасностью». Новая страница должна точно показывать роль продукта.

Phantom — система регистрации переговоров, а **не**:

- DLP;
- SIEM;
- антифрод;
- система предотвращения мошенничества;
- система контроля банковских транзакций;
- средство предотвращения хищений;
- система защиты банковской тайны;
- средство автоматического выявления нарушителей.

Не писать:

- «предотвращает утечки»;
- «предотвращает мошенничество»;
- «обеспечивает банковскую безопасность»;
- «гарантирует банковскую тайну»;
- «формирует доказательную базу»;
- «исключает финансовые потери».

Правильная роль продукта: **фиксировать коммуникацию и предоставлять запись для последующего внутреннего разбора, проверки исполнения процедур, анализа спорных ситуаций и контроля качества взаимодействия**.

## 8. Секция «Когда содержание разговора нужно восстановить точно»

H2:

```text
Когда содержание разговора нужно восстановить точно
```

Вводный текст:

```text
Телефонный разговор может содержать распоряжение клиента, подтверждение действий сотрудника, консультацию по продукту или внутреннее поручение. Если позднее возникает вопрос о том, что именно было сказано и когда, запись становится источником фактической информации для внутреннего разбора.
```

Карточки:

### Распоряжения клиентов
```text
Запись позволяет восстановить содержание обращения клиента, время разговора и действия сотрудника после полученного распоряжения.
```

### Спорные ситуации
```text
Если клиент и сотрудник по-разному описывают содержание консультации или договорённости, можно обратиться к сохранённому разговору и проверить фактическую последовательность коммуникации.
```

### Внутренний контроль
```text
Уполномоченные подразделения могут использовать записи для проверки соблюдения внутренних процедур и качества работы с клиентами.
```

Не утверждать, что запись автоматически доказывает правоту банка.

## 9. Сценарий платёжной карты

H2:

```text
Распоряжение клиента должно быть связано со временем и содержанием разговора
```

Текст:

```text
Один из сценариев, описанных МДИС, — обращение держателя банковской карты, например при её утрате или подозрении на компрометацию. Для последующего разбора важно установить, когда клиент обратился в банк, какое распоряжение передал и какие действия выполнил сотрудник.
```

Показать четыре вопроса:

- Когда поступило обращение?
- Кто передал распоряжение?
- Что именно сообщил клиент?
- Какие действия и когда выполнил сотрудник?

Завершение:

```text
Автоматическая запись разговора вместе с доступными данными о времени и канале связи помогает восстановить эту последовательность без опоры только на память участников.
```

Не превращать пример в универсальную юридическую норму о сроках блокировки счёта.

## 25. Правовая аккуратность

Без точного официального источника **не утверждать**:

- обязательность записи всех разговоров;
- конкретный срок хранения;
- соответствие нормативам Банка России;
- соответствие 152-ФЗ как характеристику продукта;
- соответствие требованиям банковской тайны;
- соответствие PCI DSS;
- юридическую силу фонограмм.

Использовать нейтральную формулировку:

```text
Срок хранения, перечень записываемых линий, порядок доступа и требования к защите информации определяются внутренними правилами организации и применимыми нормативными требованиями.
```

## 26. Что не делать

Не:

- менять production `mdis.ru`;
- менять общую дизайн-систему;
- создавать новый header/footer;
- приписывать Phantom DLP, антифрод, речевую аналитику, биометрию, WORM, криптографию;
- обещать предотвращение мошенничества или утечек;
- писать о юридической доказательности;
- придумывать сроки хранения;
- заявлять совместимость с любой CRM;
- использовать «совместимо с любой АТС» как абсолют;
- придумывать детали проектов Сбербанка и Райффайзен Банка;
- использовать выражение «реальное оборудование»;
- создавать фиктивный контент ради выравнивания карточек.

## 27. Техническая проверка

После изменений:

1. `financial.html` открывается самостоятельно.
2. Один H1.
3. Корректная H1 → H2 → H3.
4. Есть `noindex, nofollow`.
5. Используется общий header.
6. Используется общий footer.
7. Работают светлая и тёмная темы.
8. Работает `solutions-switcher`.
9. Пункт «Финансовые организации» в меню локальный.
10. Ссылка на странице Phantom Home локальная.
11. CRM ведёт на `index.html`.
12. Phantom Pro 5 и 6 ведут на локальные страницы.
13. Нет ссылок на случайный корень `/`.
14. Нет горизонтального overflow.
15. Если есть браузер — проверить 375, 768, 1024, 1440 px в обеих темах.
16. Если браузерного теста не было — не заявлять, что он выполнен.

Работа принята, если:

- страница встроена в header, Phantom Home и `solutions-switcher`;
- production `mdis.ru` не затронут.
