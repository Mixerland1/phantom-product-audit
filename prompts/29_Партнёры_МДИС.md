# 10. Проверить актуальность Astra badge

Перед публикацией:

1. открыть текущую `https://mdis.ru/about/partners/`;
2. проверить сам badge/изображение;
3. определить, что именно означает маркировка `2027`;
4. если есть отдельный текущий документ или страница Astra Linux — использовать её;
5. не превращать год на картинке в самостоятельный юридический срок без источника.

Если смысл badge не удаётся подтвердить:

использовать:

```text
На текущей партнёрской странице МДИС опубликован badge Astra Linux с маркировкой 2027.
```

а не:

```text
партнёрство гарантированно действует до конца 2027 года.
```

# 17. География ≠ эксклюзивность

Наличие партнёра в конкретной стране не означает:

- эксклюзивные права;
- единственного дилера;
- единственного сервисного партнёра;
- территориальную монополию.

Не использовать:

```text
официальный представитель МДИС в Казахстане
```

если это прямо не подтверждено.

---

# 18. Партнёры ≠ клиенты

Если организация присутствует и в `clients.html`, и в `partners.html`, не делай вывод самостоятельно.

Одна компания может участвовать:

- как интегратор;
- как заказчик;
- в разных проектах в разных ролях.

На `partners.html` использовать только информацию из партнёрского источника.

Если `clients.html` существует:

не перелинковывать каждую совпадающую организацию без причины.

---

# 19. Партнёры ≠ совместимость

Наличие компании в партнёрском списке не означает:

```text
Phantom совместим со всем оборудованием этого производителя
```

Например, даже если есть партнёрство с технологическим вендором:

совместимость должна подтверждаться:

- конкретной моделью;
- версией;
- протоколом;
- официальным тестом/документом.

Это обязательное правило.

- скидки;

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
- Не менять production `mdis.ru`.

### Финальный отчёт

Помимо обычного отчёта промпта обязательно добавить `Integration manifest`: созданные page-owned файлы, необходимые изменения общих файлов, зависимости, выполненные и невыполненные проверки.
