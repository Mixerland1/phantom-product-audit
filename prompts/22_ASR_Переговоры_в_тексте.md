# 6. Критическое ограничение: ASR ≠ «ИИ-аналитика»

Не приписывать модулю без отдельного официального подтверждения:

- суммаризацию разговора;
- поиск по смыслу;
- semantic search;
- определение эмоций;
- sentiment analysis;
- определение конфликтности;
- автоматическую оценку качества звонка;
- речевую аналитику;
- автотеги;
- автокатегоризацию;
- выделение ключевых слов;
- speaker diarization;
- разделение ролей `оператор / клиент`;
- определение пола/возраста;
- распознавание именованных сущностей;
- определение тем;
- генерацию резюме;
- LLM;
- GPT;
- RAG;
- автоматические рекомендации;
- выявление нарушений;
- автоматическое формирование отчётов;
- автоматическую проверку скриптов.

Если такие функции позже найдены в отдельной официальной документации МДИС, их можно добавить только после прямого подтверждения.

# 7. ASR ≠ поиск по тексту автоматически

Факт наличия текстовой расшифровки **не доказывает**, что система поддерживает:

- полнотекстовый поиск по транскрипту;
- поиск фраз;
- фильтрацию по словам;
- индексацию текста;
- подсветку совпадений.

Если это не указано в официальной документации, не писать:

```text
найдите нужный звонок по фразе
```

или:

```text
поиск по содержанию разговоров
```

Допустимая формулировка:

```text
ASR создаёт текстовое представление записи, которое можно читать вместо полного прослушивания аудио.
```

---

# 8. Аудио остаётся исходной записью

Очень важно не создавать впечатление, что после ASR аудио больше не нужно.

```text
ASR дополняет аудиозапись текстом. Исходным материалом остаётся зарегистрированный разговор, а транскрипт предоставляет дополнительный способ ознакомиться с его содержанием.
```

Не писать:

```text
текст заменяет запись
```

или:

```text
после распознавания аудио можно удалить
```

# 10. Не обещать точность распознавания

Официальная новость не публикует:

- процент точности;
- WER;
- CER;
- качество на шуме;
- качество на телефонном канале;
- качество на радио;
- качество на разных языках;
- качество на профессиональной терминологии.

Следовательно, запрещено писать:

- `точность 95%`;
- `почти без ошибок`;
- `высокая точность`;
- `распознаёт даже шумную речь`;
- `понимает отраслевую терминологию`.

Использовать нейтрально:

```text
Качество распознавания зависит от качества исходной записи и условий разговора; численные показатели точности МДИС в опубликованной новости не приводит.
```

# 12. Не придумывать режим обработки

Источник не сообщает, работает ASR:

- в реальном времени;
- после завершения разговора;
- по очереди;
- пакетно;
- локально;
- на отдельном сервере;
- через облако.

Следовательно, не писать:

```text
расшифровка появляется мгновенно
```

или:

```text
транскрибация в real time
```

или:

```text
обработка выполняется полностью локально
```

без документации.

Корректно:

```text
Официальная публикация подтверждает преобразование сохранённой аудиозаписи в текст, но не описывает архитектуру и время обработки.
```

# 44. Не путать ASR с распознаванием говорящего

Без официального источника не писать:

- voice biometrics;
- определение конкретного человека;
- разделение голосов;
- определение роли говорящего.

# 45. Не путать ASR с записью

ASR не должен выглядеть самостоятельной системой, которая сама подключается к АТС.

Правильная схема:

```text
АТС / линия / IP
       ↓
МЦКРС «Фантом»
       ↓
аудиозапись
       ↓
ASR
       ↓
текст
```

Не рисовать ASR напрямую подключённым к телефонной инфраструктуре.

# 50. Критерий готовности

Работа считается выполненной, если:

- создан `phantom-asr.html`;
- ASR представлен как дополнительный модуль Phantom;
- прямо подтверждено только преобразование аудио в текст;
- аудиозапись сохранена как исходный материал;
- ASR не выдан за речевую аналитику;
- не придуманы поиск, summary, sentiment, diarization или AI-функции;
- не придуманы языки и точность;
- не придумана внутренняя архитектура модуля;
- страница связана с Phantom Cross, главной и страницами записи;
- ASR не добавлен в аппаратную линейку;
- production `mdis.ru` не затронут.
