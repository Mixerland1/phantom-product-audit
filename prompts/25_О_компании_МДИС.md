# 2. Главная задача страницы

Старая страница:

https://mdis.ru/about/

содержит полезные факты, но также много устаревших или чрезмерно рекламных формулировок:

- `совместимость с любой АТС`;
- `лучший аппаратный комплекс`;
- `самый большой список поддерживаемых АТС`;
- `самый надёжный, высокотехнологичный и универсальный продукт`;
- `для нас нет нерешаемых задач`;
- `в любых условиях`;
- `в любой точке мира`;
- счётчики `7000 проектов`, `70 аэропортов`, `9 АЭС` без очевидной даты актуализации.

Новая страница должна отвечать на более конкретные вопросы:

> кто такая МДИС, что компания разрабатывает, с какого времени работает, какие компетенции подтверждены реальными продуктами и проектами, где посмотреть историю, клиентов, партнёров, сертификаты и реквизиты.

# 14. Клиенты: не делать неподтверждённый счётчик

Старая страница содержит:

```text
7000 реализованных проектов
70 аэропортов
9 атомных электростанций
```

Эти цифры не использовать автоматически.

Алгоритм:

1. найди свежий официальный источник с датой, подтверждающий каждую цифру;
2. если такого источника нет — **не показывай счётчик**;
3. не обновляй число самостоятельно по спискам клиентов;
4. не пиши `более 7000`, если это просто старый счётчик.

Вместо KPI можно использовать:

```text
Проекты в энергетике, атомной отрасли, авиации, промышленности, государственном и коммерческом секторе.
```

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
- Не менять production `mdis.ru`.

### Финальный отчёт

Помимо обычного отчёта промпта обязательно добавить `Integration manifest`: созданные page-owned файлы, необходимые изменения общих файлов, зависимости, выполненные и невыполненные проверки.
