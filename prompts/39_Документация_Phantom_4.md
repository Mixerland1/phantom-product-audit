# 4. Главное позиционирование

Phantom 4 — это **Windows-ветка ПО Phantom 4.x**.

Не смешивать её с:

```text
Phantom Cross 5.x
```

которая относится к Astra Linux.

На новой странице сразу должно быть понятно:

```text
Phantom 4.x → Windows-ветка
Phantom Cross 5.x → Astra Linux-ветка
```

Если `support-phantom-cross.html` существует:

дать secondary link:

```text
Документация Phantom Cross 5.5 →
```

# 5. Не называть Phantom 4 legacy, если МДИС сама продолжает считать ветку актуальной

Текущий FAQ МДИС сообщает:

```text
ПО «Фантом» версия 4.10 является актуальной
```

и указывает поддержку Windows до:

```text
Windows 10
Windows Server 2016
Windows Server 2019
```

Но перед публикацией:

1. проверить актуальность этой формулировки на текущем `mdis.ru`;
2. проверить сами документы 4.x;
3. не использовать слово `legacy`, если официальный сайт продолжает поддерживать ветку;
4. одновременно не называть Phantom 4 «основной современной платформой», если новая Linux-ветка Cross уже существует.

Предпочтительная формулировка:

```text
Поддерживаемая Windows-ветка Phantom 4.x для существующих и совместимых конфигураций.
```

Только если это подтверждается текущими материалами.

# 42. Критерий готовности

Работа считается выполненной, если:

- создан `support-phantom-4.html`;
- страница доступна из `support.html`;
- Phantom 4 явно отделён от Cross 5.x;
- Windows-ветка описана без устаревшей compatibility speculation;
- все актуальные восемь материалов подключены;
- VoIP manual не выдан за universal compatibility;
- старые ОС не показаны как recommended current;
- дистрибутив не выдуман;

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
