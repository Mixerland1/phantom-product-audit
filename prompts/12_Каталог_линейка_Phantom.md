`Mixerland1/phantom-product-audit`

Базовая ветка проекта: `main`.

## Режим параллельной разработки — обязательно

Этот промпт выполняет **page-agent** в отдельной ветке/worktree. `main` — только базовая ветка.

### Владение файлами

Page-agent может создавать и менять только:
- целевую страницу этого промпта;
- уникальные assets, используемые только этой страницей;
- локальные стили этой страницы, если они необходимы.

Page-agent может читать, но **не должен изменять**:
- `assets/site-header.js`;
- `assets/footer-next.js`;
- `phantom-home.html`;
- `AGENTS.md`;
- `docs/PHANTOM_SYNC_WORKFLOW.md`;
- общие CSS/JS;
- страницы других параллельных задач.

Если ниже по промпту требуется изменить общий файл, считать это **требованием для Integrator**. Не выполнять такую правку в page-ветке; перечислить её в финальном `Integration manifest`.

### Актуальность

Статические примеры общего header, `solutionPages`, порядка соседних страниц и других общих компонентов в этом промпте могли устареть. Не откатывать актуальный проект ради совпадения с примером. Текущее состояние базового `main` и правила `prompts/README.md` имеют приоритет для интеграции.

### Git и публикация

- Зафиксировать базовый commit SHA.
- Не коммитить напрямую в `main`.
- Не сливать свою ветку в `main`.
- Не публиковать на AEZA.
- Не менять production `mdis.ru`.

### Финальный отчёт

Помимо обычного отчёта промпта обязательно добавить `Integration manifest`: созданные page-owned файлы, необходимые изменения общих файлов, зависимости, выполненные и невыполненные проверки.

# 4. Какие старые формулировки нельзя переносить как есть

Старая страница использует слишком абсолютные заявления:

```text
решения для АТС всех производителей
```

```text
запись всех видов телефонии
```

```text
безопасная передача и защищённое хранение
```

как универсальные свойства любой конфигурации.

На новой странице использовать более точную формулировку:

```text
МЦКРС «Фантом» поддерживает несколько способов подключения к аналоговой, цифровой и IP-телефонии. Конкретные интерфейсы и совместимость определяются выбранным исполнением, АТС, версией ПО и архитектурой проекта.
```

Не писать:

- `совместима с любой АТС`;
- `поддерживает все АТС`;
- `поддерживает все протоколы`;
- `любое количество каналов`;
- `полная защищённость`;
- `гарантированная сохранность`.

# 49. Критерий готовности

Работа считается выполненной, если:

- создан `phantom-catalog.html`;
- страница стала центральным продуктовым хабом Phantom;
- старое содержательное ядро `/catalog/` не потеряно;
- продукты разделены на готовые регистраторы, платы, способы IP-записи и специализированные системы;

- схемы подключения сохранены как отдельное направление с временной ссылкой до следующей миграции;

- нижняя ссылка меню «Продукты» ведёт в каталог;
- Phantom Home ведёт в новый каталог;
- generic product pages возвращаются в каталог;
- существующие подробные страницы не переписаны без необходимости;
